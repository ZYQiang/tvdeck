# tvdeck

通用 ADB 设备管理 Web 工作台。

把局域网里的 Android 设备——电视、机顶盒、投影仪、手机、平板——接进一个网页：设备发现与连接、实时屏幕、遥控操作、应用管理、显示与电源控制、健康监控、任务自动化，全部开箱即用。

**几个刻意坚持的设计原则：**

- **零第三方依赖**：后端只用 Node.js 标准库，前端是原生 HTML/CSS/JS，不需要 `npm install`
- **厂商无关，不假设 root**：只走 AOSP 公开接口（`pm` / `cmd` / `settings` / `dumpsys`），康佳、小米、索尼、海信等设备走同一条路径；每条能力先探测再执行，设备不支持就直说不支持
- **所有写操作回读验证**：状态读不回来就标记 `verified: false`，任何破坏性动作都先存快照，页面上一键还原
- **单进程、单命令启动**：`npm start` 跑起来，浏览器打开就是完整工作台

## 功能一览

| 功能 | 说明 |
| --- | --- |
| 设备发现与连接 | 扫描局域网开放 ADB 的设备（5555 端口）、通过 adb mDNS 发现 Android 11+ 无线调试设备、手动输入 IP:端口直连、一键重连上次设备 |
| 实时设备屏幕 | 直接抓取设备屏幕直播（一路抓屏多端共用，约 5 fps），支持全屏、纯画面页、画面比例切换、一键截图下载 PNG |
| 服务端画面 | 抓取运行 tvdeck 的主机屏幕推给其他浏览器观看（macOS 用系统 `screencapture`，Windows/Linux 用 ffmpeg `gdigrab`/`x11grab`），适合把采集卡 / scrcpy 窗口的内容分享出去 |
| 遥控与输入 | 方向 / OK / 返回 / 主页等语义按键（自适应各品牌 keylayout 扫描码）、长按、鼠标与触控（点按 / 滑动）、文字输入 |
| 应用管理 | 全量应用清单（含预装）+ 图标 + 名称解析、启动 / 强制停止 / 卸载 / 清除数据、APK 安装（主机文件或上传）、设备文件浏览（系统分区只读保护）与主机间互传 |
| 显示设置 | 亮度调节、护眼模式开关、PQ 显示参数读取 |
| 电源控制 | 休眠 / 唤醒 / 关屏，配合自动化可做定时开关机 |
| 屏幕录制 | 设备端录屏 5–30 秒，可选 1080p / 720p，录完直接下载 |
| 设备诊断 | 系统信息、进程列表、文件系统检查、设备健康快照、完整操作日志 |
| 使用记录 | 屏幕使用时间、前台应用时长统计 |
| 系统配置 | 启动项、默认桌面、开机自启管理（先探测再执行，写后回读验证） |
| 任务自动化 | 把按键、启动应用、调音量、护眼、电源、输入文字、打开网址、播放媒体、等待九类动作串成脚本；支持手动执行、每天定点、设备上线自动触发三种方式 |
| 媒体库 | 图片 / 视频 / 音频上传，设备端直接 HTTP 拉流播放（支持 Range，不转码）；可选先推送到设备本地再全屏播放 |
| 开机自启 helper | `tools/tvdeck-boot` 提供一个厂商无关的辅助 APK，开机后按配置自动拉起目标应用（广播 + 无障碍服务双通路） |

页面自带手机优先的窄屏适配，手机浏览器打开同一地址也能操作。

## 环境要求

| 依赖 | 用途 | 必需性 |
| --- | --- | --- |
| Node.js ≥ 23.6 | 后端运行时（原生跑 TypeScript，无需编译步骤） | 必需 |
| adb（Android platform-tools） | 与设备通信 | 必需，需在 `PATH` 中 |
| ffmpeg | Windows / Linux 上的「服务端画面」抓屏 | 可选 |
| macOS 屏幕录制权限 | macOS 上的「服务端画面」抓屏 | 可选 |

## 快速开始

```bash
# 1. 确认 adb 可用
adb version

# 2. 启动服务
npm start
```

打开 `http://localhost:8787`（服务监听 `0.0.0.0`，局域网内其他设备也能访问）。首次使用建议按顺序：

1. 进入 **设备连接**，扫描局域网或手动输入 `IP:端口` 连接设备
   （设备侧需先打开：设置 → 开发者选项 → 网络 ADB 调试 / 无线调试）
2. 首次连接会自动探测设备能力并生成档案（`.tvdeck/profile.json`）
3. 之后就能用遥控、镜像、应用管理等全部功能

### CLI 工具

```bash
npm run discover [-- --full]   # 扫描局域网 ADB 设备
npm run probe [ip] [-- --full] # 深度探测设备，生成 .tvdeck/profile.json
npm run mirror-check           # 验证服务端抓屏权限与工具链
npm run icons                  # 从设备 APK 提取应用图标，建立图标索引
```

## 目录结构

```
src/
  server.ts        HTTP 服务、API 路由、自动化调度
  cli.ts           命令行入口
  adb.ts           adb 进程封装（超时、二进制安全输出）
  discover.ts      局域网设备发现（端口扫描 + adb mDNS）
  probe.ts         设备能力探测与取证落盘
  profile.ts       设备档案读写
  commands.ts      按键 / 音量 / 电源 / 护眼 / 文字输入等设备命令
  input.ts         语义键名 → keylayout 扫描码解析（跨品牌自适应）
  mirror.ts        设备屏幕直播、服务端画面、MJPG 推流
  media.ts         媒体库与 Range 流式播放
  manage.ts        应用 / 文件 / 进程管理
  system.ts        启动项 / 默认桌面 / 开机自启（AOSP 接口）
  automation.ts    自动化脚本引擎（白名单动作 + 三种触发器）
  names.ts         应用名称缓存（一次解析，四处共用）
  icons.ts         应用图标索引
  home.ts          数据目录与资源目录定位
public/            前端页面
  index.html       主工作台（总览 / 遥控 / 应用 / 显示 / 诊断 / 任务 / 连接 / 配置）
  screen.html      设备画面纯屏页（只放画面，无控制台）
  watch.html       服务端画面观看页
scripts/           辅助脚本（图标提取等）
tools/tvdeck-boot  开机自启 helper APK（Java 源码 + 构建脚本 + 预编译产物）
```

## 数据存储

所有运行数据默认落在项目目录下的 `.tvdeck/`（设备档案、应用名缓存、自动化脚本、媒体库、还原快照、录屏产物）。设置环境变量 `TVDECK_HOME` 可指定其他位置，方便把数据和代码分开。

服务端口通过 `PORT` 环境变量覆盖，默认 `8787`。

## 安全须知

- 自动化脚本只执行**白名单动作**，绝不执行任意 shell——这条通路能远程操作设备，放开任意命令等于把服务变成局域网内的远程命令执行点
- 文件管理对系统分区只读，避免误删
- 服务默认监听 `0.0.0.0`，**局域网内任何人都能访问**。请只在可信网络中运行；如需对外暴露，请自行加反向代理与认证
- 系统配置的破坏性动作（改默认桌面、清启动项等）会先存快照，出问题可在页面一键还原

## 常见问题

**扫描不到设备？**
设备侧打开「网络 ADB 调试」或「无线调试」；部分电视需在设置里连按版本号开启开发者选项。Android 11+ 的无线调试随机端口依赖 adb 的 mDNS 报告，确保 adb 版本较新。

**「服务端画面」全黑或报错？**
macOS：系统设置 → 隐私与安全性 → 屏幕录制，勾选运行 tvdeck 的终端 / Node，然后重启服务。Windows/Linux 需要安装 ffmpeg。

**应用没有图标或显示为包名？**
运行 `npm run icons` 从设备 APK 提取图标；名称会在首次访问时解析并缓存到 `names.json`。

**自动化脚本没跑？**
确认脚本已启用；「每天定点」按服务端本机时区判断，「设备上线」触发会在设备连上后再等一段缓冲时间（可配）。
